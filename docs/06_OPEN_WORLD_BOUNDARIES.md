# CreatiBox Open World Freedom & Boundary Model V0.1

## 1. 目的

本文件定义 CreatiBox 中学生到底拥有多大自由，以及哪些数据可以直接修改、哪些只能通过世界运行产生变化、哪些由系统计算。

CreatiBox 的目标不是无限制修改一切，而是提供：

> 高创作自由 + 明确因果关系 + 可理解的世界规则

## 2. 最终自由度模型

学生的创作自由分为四个层级：

1. 创建实体
2. 定义实体能力
3. 定义实体之间的关系与后果
4. 调整世界规则允许暴露的参数

学生不是直接改程序，而是在安全模型中定义世界。

## 3. Layer A：Design Parameters 设计参数

这些参数代表“创造这个东西时，它本来是什么样”。学生可以在编辑模式中直接修改。

例如赛车：颜色、大小、初始位置、最大速度、加速度、重量、初始耐久度、转向灵敏度。

例如人物：外观、初始位置、最大生命值、移动速度、跳跃能力。

例如树：初始大小、生长速度、最大高度、初始健康度。

这些数据属于“作者设定”。

## 4. Layer B：Runtime State 运行状态

这些数值代表世界运行后当前发生了什么。默认情况下，学生不能在运行模式中直接任意修改。

例如赛车：当前速度、当前耐久度、当前方向、是否受损、是否翻倒。

例如人物：当前生命值、当前体力、当前状态、当前位置。

例如树：当前年龄、当前高度、当前健康度、当前生命周期阶段。

示例：Car durability = 100 → Car collides with Wall → Damage = 30 → durability = 70。

学生不能在运行中直接点一下把 70 改回 100，但可以创造 Repair Station，并定义“进入 Repair Station → Repair +30”。

## 5. Layer C：Derived Values 派生参数

有些数据不应该由学生直接输入，而应由系统根据其他参数计算。

例如：碰撞强度、实际伤害、当前动量、剩余百分比、成熟度、建筑损伤等级。

早期版本可以使用简化公式，而不追求真实物理。

## 6. Layer D：System Constants 系统常量

部分底层规则由 CreatiBox Runtime 控制，学生不能直接修改。

例如：世界更新频率、Runtime 安全限制、允许执行的 Action 类型、JSON Schema、最大对象数量、数值安全范围、文件访问权限、浏览器权限、任意代码执行权限。

## 7. 四层修改权限

| 数据类型 | 编辑模式 | 运行模式 | 修改方式 |
|---|---|---|---|
| Design Parameters | 可修改 | 默认锁定 | 学生直接设置 |
| Runtime State | 可设置初始值 | 不直接修改 | Action / Interaction 改变 |
| Derived Values | 不直接修改 | 自动计算 | Runtime 计算 |
| System Constants | 不可修改 | 不可修改 | 平台控制 |

## 8. 核心原则：自由来自“创造机制”，不是“直接改结果”

不是把生命值直接改成 100，而是创造“吃苹果 → 恢复生命值 20”。

不是把树直接改成成熟，而是创造“浇水 + 时间经过 → 生长 → 成熟”。

真正的开放世界自由，是学生可以设计因果关系。

## 9. 数值展示

数值存在，不代表一定展示。学生可以选择某个数值是否公开，以及如何显示。

可选显示方式：数字、进度条、血条、图标、隐藏。

赛车耐久度可以显示为 80%，人物生命值可以显示为 HP 72 / 100，树木健康值也可以完全隐藏，只通过叶子颜色表现。

## 10. Interaction 必须允许影响双方

例如 Car collides with Barrier，可以同时影响：

- Car：速度下降、耐久度下降、状态变为 Damaged
- Barrier：耐久度下降、位置变化、状态变为 Damaged
- World：播放声音、产生火花、生成烟雾、改变分数

因此 Interaction 应支持多个 Effect，而不是只修改一个对象。

## 11. 因果链

CreatiBox 应允许关系形成连续因果链：

赛车撞路灯 → 赛车受损 → 路灯倒下 → 路灯砸到木箱 → 木箱破裂 → 钥匙出现 → 玩家拾取钥匙 → 大门可打开。

系统底层必须支持：Interaction → State Change → Trigger → New Interaction → New State Change。

## 12. 生命周期

生命周期同样由状态驱动。

例如 Tree：Seed → Plant → Sprout → Grow → Young → Grow → Mature → Damage/Age → Weak → Cut/Storm → Fallen → Decay → Removed。

学生可以调整阶段参数、触发条件、不同阶段允许的动作，但运行时变化应由规则造成。

## 13. 编辑模式与运行模式必须分开

### Edit Mode

学生是世界作者，可以创建实体、删除实体、设置初始属性、设置最大值、定义能力、定义规则、定义关系、设置数值显示方式。

### Play Mode

学生进入自己创造的世界。状态由规则变化，数值由行为变化，Interaction 产生后果，不能直接任意修改运行状态。

## 14. 推荐开放边界

### 学生可以直接修改

- 实体类型
- 数量
- 初始位置
- 大小
- 方向
- 外观
- 初始值
- 最大值
- 能力开关
- Interaction Rules
- State Transition Rules
- 数值是否显示

### 学生通过规则间接修改

- 当前生命值
- 当前耐久度
- 当前速度
- 当前年龄
- 当前成长阶段
- 当前损坏程度
- 当前能量
- 当前世界状态

### 学生不能修改

- Runtime 核心实现
- 任意代码执行
- 浏览器或文件系统权限
- 未注册 Action
- Schema
- 安全上下限
- 系统内部事件循环

## 15. 最终产品自由度

一个成熟的 CreatiBox 项目中，学生应该能够创造：

对象 → 属性 → 能力 → 行为 → 关系 → 状态变化 → 因果链 → 生命周期 → 关卡 / 世界。

因此最终作品不是“摆出来的一张场景图”，而应该是：

> 一个会自己发生事情的世界。
