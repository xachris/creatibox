# CreatiBox 赛车音效系统设计 V0.1

## 1. 文档目的

本文定义 Racing Creator 第一版可落地的**音效设计**，回答三件事：

1. 比赛里哪些时刻必须出声（否则“没感觉”）
2. 声音怎么分层、怎么跟现有 `soundPreset` 挂钩
3. 实现时先做哪一批、资产清单是什么

本轮**只做设计**，不引入音频库、不提交音频文件、不改运行时播放逻辑。

产品事实基线：

- 启动流程已让学生选择 **Light / Sport / Electric**（`SoundPreset`）
- 选择会写入车辆 `soundPreset`，但**尚未真正播放**
- 比赛阶段已有：`countdown` → `racing` → `finished`
- 玩家输入已有：加速、强加速（Space）、刹车、转向
- 技术栈已锁定 **Howler.js** 做播放；**Tone.js** 留给未来音乐 Creator，不用于本轮赛车 SFX

---

## 2. 设计目标

### 必须达到

- 从倒计时到冲线，听感上形成完整“一场比赛”
- 油门、行驶、松油门减速、刹车，听感可区分
- 三种声音族听起来明显不同，学生选择有意义
- 课堂环境：可静音、可调音量、无云端依赖、体积可控

### 明确不做（V0.1）

- 不给每辆电脑车单独完整引擎轨（教室嘈杂 + CPU 浪费）
- 不做可编辑的音乐编曲 / DAW
- 不依赖在线 CDN 或流式音频
- 不做空间 3D 定位（左右声道简单偏置可留到以后）
- 不把音效写死在“赛车专用引擎”里——播放层应落在未来的 `media/sound`，由世界事件驱动

---

## 3. 听感原则

1. **仪式感优先于拟真**  
   倒计时、GO、胜利对课堂冲击最大，应最先做实。
2. **连续层 + 一次性层**  
   引擎是持续循环；喇叭、碰撞、完赛是短音。
3. **由状态驱动，不由按钮名驱动**  
   学生可能改键位；音效应跟速度、是否在刹、是否碰撞、比赛阶段挂钩。
4. **族是皮肤，事件是骨架**  
   `light` / `sport` / `electric` 只换音色包；事件表三族共用。
5. **先解锁再出声**  
   浏览器自动播放策略：在学生点击「开始比赛」时解锁 AudioContext，倒计时才能准时响。

---

## 4. 声音分层

| 层 | 作用 | 典型内容 | 同时播放？ |
| --- | --- | --- | --- |
| A. 仪式 / UI | 比赛节奏与结果 | 倒计时滴、GO、胜利、失败、可选 UI 点击 | 可叠在引擎上，但完赛后引擎应淡出 |
| B. 玩家引擎 | 车“活着”的主体感 | 怠速、加速、巡航、减速 | **同一时刻只保留一条引擎逻辑轨**（可用多 clip 交叉淡化） |
| C. 操作反馈 | 刹车、急转（可选） | 刹车摩擦、轻量胎噪 | 短循环或 one-shot，可与引擎叠 |
| D. 世界冲击 | 撞墙 / 撞障 / 撞车 | 碰撞钝响 | one-shot，带短冷却防刷屏 |
| E. 环境（可选，V0.1 可空） | 氛围 | 人群、风噪 | 低音量床声；首版可省略 |

V0.1 范围：**A + B + C（刹车）+ D**。E 不做。

## 5. 事件表（必须有声）

下列事件与当前运行时直接对应，是本设计的验收清单。

### 5.1 比赛仪式（与 `RunPhase` 对齐）

| 事件 ID | 触发条件（实现侧） | 听感意图 | 播放类型 | 打断规则 |
| --- | --- | --- | --- | --- |
| `race.countdown.tick` | `phase === 'countdown'`，整数秒从 3→2→1 各触发一次 | 紧张、清晰、可数拍 | one-shot | 不叠同一个 tick |
| `race.countdown.go` | 进入 `racing` 的瞬间（或 UI 显示 `GO!`） | 释放、出发 | one-shot | 可与怠速同时起 |
| `race.finish.win` | `phase === 'finished'` 且玩家在 `finishOrder` 第 1 | 胜利、庆祝 | one-shot | 引擎 150–300ms 内淡出 |
| `race.finish.place` | 玩家完赛但非第 1 | 完成感，弱于胜利 | one-shot | 同上 |
| `race.finish.broken` | 玩家 `Broken` 导致结束 | 短促失败 / 熄火 | one-shot | 引擎立刻停 |

说明：用户说的「前面的启动」= 倒计时 + GO；「最后的胜利」= `race.finish.win`（非第一用 `place`，损坏用 `broken`）。

### 5.2 玩家车辆动态（与速度 / 输入对齐）

引擎不按“按了哪个键”硬编码，而按下面的**驾驶态**切换：

| 驾驶态 | 判定（建议） | 事件 / 层 | 听感 |
| --- | --- | --- | --- |
| `idle` | `racing` 中且 `speed ≈ 0`，未在刹 | `engine.idle` 循环 | 低音量怠速 |
| `accel` | 正在加速（普通或 Space 强加速）且速度上升 | `engine.accel` → 过渡到 cruise | 转速抬升 |
| `cruise` | `speed` 较高且油门仍按住，速度接近平台 | `engine.cruise` 循环 | 持续行驶感 |
| `coast` | 松开油门、未刹车、速度仍 > 0（自然减速） | `engine.coast` 或降低 cruise 速率 | 泄力、减速 |
| `brake` | 刹车键按下且 `speed > 阈值` | `tire.brake`（C 层）+ 引擎降速 | 刹车摩擦；停稳后停掉 |

实现建议（不必首版就完美）：

- 用 **playbackRate / 音量** 跟 `speed / maxSpeed` 连续映射，比硬切五个文件更省资产、更跟手
- Space 强加速可比普通加速略提高音量或速率上限，但不强制第二套引擎样本
- 从 `idle → accel → cruise` 用短 crossfade（约 80–160ms），避免爆音

### 5.3 世界冲击

| 事件 ID | 触发 | 听感 | 规则 |
| --- | --- | --- | --- |
| `world.collision` | 玩家车新产生碰撞接触（`contacts` 新增） | 钝击 / 刮擦 | 同一对实体冷却 ≥ 200ms；音量可随相对速度粗调 |

电脑车碰撞：V0.1 **默认可不发声**，或极低音量共用一个通用碰撞音，避免声场混乱。

## 6. 三种声音族（已有产品选择）

学生选的是**族**，不是单个文件。

| `SoundPreset` | 听感定位 | 引擎倾向 | 仪式音是否换皮 |
| --- | --- | --- | --- |
| `light` | 轻快、干净、偏高 | 细、亮、压缩感弱 | 可用同一套仪式音，或更轻的胜利音色 |
| `sport` | 厚、冲、攻击性 | 低吼、油门响应猛 | 默认推荐族；仪式音可略“赛道感” |
| `electric` | 科幻、干净、转速线性 | 电子呜鸣、随速度音高更明显 | 胜利可用更合成的音色 |

V0.1 最小差异要求（验收）：

- 同一条加速动作，闭眼能分出至少两族不同
- 仪式音（倒计时 / GO / 胜利）三族可共用一套 UI 包；**引擎包必须分族**

默认启动选择已是 `sport`，设计上以 Sport 为“主音色参考”，另外两族做变体。

## 7. 资产清单（建议目录）

建议落在：

```text
public/audio/
  ui/                 # 仪式与界面，族无关或弱相关
  engines/
    light/
    sport/
    electric/
  world/              # 碰撞等
```

### 7.1 UI / 仪式（优先制作）

| 文件（建议 ID） | 用途 | 预估时长 | 备注 |
| --- | --- | --- | --- |
| `ui/countdown_tick.webm` 或 `.ogg` | 3/2/1 | 0.15–0.3s | 每秒一次；可用音高微调区分 3/2/1 |
| `ui/countdown_go.webm` | GO | 0.4–0.8s | |
| `ui/finish_win.webm` | 胜利 | 1.5–3s | 可稍华丽 |
| `ui/finish_place.webm` | 完赛非第一 | 1–2s | |
| `ui/finish_broken.webm` | 损坏结束 | 0.5–1s | |

格式：优先 **OGG 或 WebM Opus**（体积小）；另备 MP3 作 Howler 回退若需要。

### 7.2 引擎族（每族一套）

每族最少：

| 文件 | 用途 |
| --- | --- |
| `idle` | 循环怠速 |
| `move` | 循环行驶底噪（用 rate/volume 覆盖 accel/cruise/coast） |

可选增强（第二批）：

| 文件 | 用途 |
| --- | --- |
| `accel_oneshot` | 起步瞬间额外一层 |
| `brake` | 该族刹车音色（也可用世界共用刹车） |

### 7.3 世界

| 文件 | 用途 |
| --- | --- |
| `world/collision.webm` | 通用碰撞 |
| `world/brake.webm` | 通用刹车（若引擎族不各自提供） |

### 7.4 资产来源策略

课堂产品需可分发：

1. **自合成**（Web Audio / 离线渲染导出）— 版权最干净，适合 V0.1 占位变可玩
2. **CC0 / 明确可商用包** — 需在仓库记录授权与来源
3. 禁止来历不明的游戏扒音

首版允许“合成占位音色”，但事件表与 API 必须按正式资产 ID 设计，避免以后换文件改代码。

## 8. 运行时架构（实现时遵循）

```text
WorldRuntime / UI 状态
        ↓  发出语义事件（上表事件 ID）
   AudioDirector（media/sound）
        ↓  查 soundPreset → 选族银行
      Howler 播放器
```

### 8.1 `AudioDirector` 职责

- `unlock()`：在「开始比赛」点击时调用
- `setMasterVolume(0..1)` / `setMuted(boolean)`
- `onRaceEvent(eventId, payload?)`
- `syncPlayerVehicle({ speed, maxSpeed, braking, accelerating, phase })`：每帧或每 50ms 更新引擎层
- `stopAll({ fadeMs })`：离开 Run、回首页、重赛前清理

### 8.2 与现有代码的挂点（设计映射，本轮不改代码）

| 现有位置 | 挂接 |
| --- | --- |
| `WorldCanvas` 进入 Run / 倒计时显示 | countdown tick、GO |
| `WorldRuntime.phase` 变化 | 仪式音 |
| `updatePlayerCar` 后的 `speed` / 刹车键状态 | 引擎与刹车 |
| `contacts` 新增 | 碰撞 |
| 结果面板出现 | win / place / broken |
| Restart / Home | `stopAll` 再按需重开 |

### 8.3 电脑车策略

- V0.1：只播**玩家**引擎 + 全局仪式音
- 可选极低音量“远处车流”床声一条（非必须）

### 8.4 课堂 UX

- Run 界面提供 **静音按钮**（教师一键）
- 记住本次会话静音偏好即可（不必进 `.creatibox`）
- 默认音量约 0.6–0.7，避免外放刺耳
- 文档提示：学生需先有一次点击才能出声（与「开始比赛」绑定，通常无感）

## 9. 实现分期（设计批准后的开发顺序）

### Phase A — 仪式感（最小可感闭环）

- 接入 Howler + `AudioDirector` 骨架
- 倒计时 tick、GO、胜利 / 完赛 / 损坏
- 静音与主音量
- **验收**：不开车也能感觉“比赛开始了 / 结束了”

### Phase B — 玩家引擎跟手

- 按 `soundPreset` 加载族
- `idle / move` + rate/volume 跟速度
- accel / coast 过渡
- **验收**：按住加速与松开，听感明显不同

### Phase C — 刹车与碰撞

- 刹车层、碰撞 one-shot + 冷却
- **验收**：刹车与撞障可分辨，且不刺耳连响

### Phase D — 三族打磨与体积

- light / electric 资产补齐与听感平衡
- 压缩体积、补授权说明
- 回归：启动流程选不同声音族，重赛不泄漏旧音频

每期完成后：更新 `docs/CHANGELOG.md` 与 `docs/16_CURSOR_AGENT_WORK_LOG.md`，并补自动测试（至少：Director 在事件下调用可 mock 的播放接口；静音时不调用 play）。

## 10. 验收标准（设计层）

满足以下即认为设计可进入编码：

1. 用户点名的能力均有事件：开动/行驶/刹车/减速、启动仪式、胜利
2. 事件表能映射到现有 `countdown | racing | finished` 与玩家车状态，无空想阶段
3. 三种已有 `soundPreset` 有明确听感分工与资产布局
4. 技术选型与仓库既有结论一致（Howler，本地包，无云端）
5. 课堂约束（静音、解锁、电脑车不多开引擎）已写明

## 13. 本轮结论

赛车“没感觉”的缺口，核心不是缺编辑器，而是缺：

**仪式音（倒计时/GO/胜负）+ 跟速度的玩家引擎 + 刹车/碰撞反馈**，并真正播发已保存的 `soundPreset`。

下一开发任务应直接从 **Phase A** 开工，而不是先扩音乐 Creator。
